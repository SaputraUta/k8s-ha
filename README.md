# k8s-ha

A **high-availability, GitOps-driven Kubernetes cluster** built from scratch on bare-metal VMs — the production-leaning successor to [**k8s-baremetal**](https://github.com/SaputraUta/k8s-baremetal).

Where v1 was "learn every piece" (single control plane, a proof of concept), this is **"do it properly": HA by design, and 100% reproducible from code — zero manual steps.**

> 🚧 In progress. Building phase by phase.

---

## What's different from v1

| | k8s-baremetal (v1) | k8s-ha (v2) |
|---|---|---|
| Control plane | 1 (single point of failure) | **3 (etcd/Raft quorum, survives 1 failure)** |
| API endpoint | node IP | **kube-vip virtual IP (floats across control planes)** |
| SSH keys / inventory | generated by hand | **generated by Terraform** |
| Secrets | `kubectl create` by hand | **ansible-vault (encrypted, in code)** |
| Storage | local-path (node-local) | **Longhorn (replicated, survives node loss)** |
| App packaging | raw manifests | **Helm chart** |
| Observability | — | **metrics + logs + dashboards** |
| Deploy | manual, then ArgoCD | **GitOps (ArgoCD) from day one** |

**Goal:** `terraform apply` + `ansible-playbook` → a full HA cluster with app, **no manual `kubectl`.**

## Planned architecture

```
        kube-vip VIP  (one stable API address)
        ┌─────┬─────┬─────┐
      cp1   cp2   cp3            ← 3 control planes, etcd quorum (Raft)
        └─────┴─────┴─────┘
             w1     w2           ← workers (app, Longhorn, observability)
```

## Stack

| Layer | Tool |
|---|---|
| IaC (VMs, keys, inventory) | Terraform (multipass + tls + local providers) |
| CaC (node + cluster config) | Ansible (+ ansible-vault for secrets) |
| Bootstrap | kubeadm (HA: `--control-plane-endpoint`) |
| HA API endpoint | kube-vip |
| CNI | Calico |
| Storage | Longhorn |
| GitOps | ArgoCD |
| Packaging | Helm |

## Layout

```
terraform/   # IaC — VMs, generated SSH key, generated Ansible inventory
ansible/     # CaC — node prep, kubeadm HA bootstrap, cluster addons
```
